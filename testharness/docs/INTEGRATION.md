# Test Harness Integration

The Python harness in this folder starts Factorio, creates a temporary save, enables an optional hidden debug startup setting, and reads a JSON report from `script-output`.

## Target Mod Requirements

A mod that wants to use this harness should provide:

- `tools/test/harness.json`: declares the mod name, debug setting, report path, expected artifacts, optional mod-list profile source, default mod-list profile, startup setting profiles, and Lua test profiles.
- `tools/test/modlist-profiles.json`: declares the mod's own compatible mod-list profiles and optional `profile_groups`.
- `tools/test/runner.lua`: builds a report table and assertion summary during the data stage or final-fixes stage.
- `tools/test/profile.lua`: generated by `run_tests.py`; do not commit a hand-edited profile unless you intentionally want a default test profile.
- `control.lua`: writes the staged report from `prototypes.mod_data` to `script-output/<ModName>/test-report.json` when a new temporary save starts.
- Usually a hidden startup setting that enables the debug/test data path.

The report transport is intentionally simple:

1. Data stage creates the report table.
2. The mod stores it in a `mod-data` prototype.
3. Runtime `control.lua` reads the mod-data value.
4. Runtime writes JSON to `script-output`.
5. Python reads and prints that JSON.

Factorio log parsing is not the primary test mechanism.

## Mod-List Profiles And Groups

Toolsets built-in profiles are intentionally limited to `vanilla` and `vanilla_dlc`. Mod-specific combinations belong in the target mod:

```text
<mod-root>/tools/test/modlist-profiles.json
```

A target mod can define compatible groups for matrix runs:

```json
{
  "profiles": {
    "my_mod": { "label": "My Mod", "mods": ["my-mod"] },
    "my_mod_dlc": { "label": "My Mod + DLC", "mods": ["my-mod", "quality", "space-age"] }
  },
  "profile_groups": {
    "all": ["my_mod", "my_mod_dlc"]
  }
}
```

With `profile_groups.all`, `--all` runs every configured test profile against every listed compatible mod profile. An explicit `--mod-profile NAME` overrides the group and runs only that one mod profile.

The harness resolves `--mod-profiles-json` in this order:

1. CLI `--mod-profiles-json`.
2. `tools/test/harness.json` field `mod_profiles_json`.
3. Target mod file `tools/test/modlist-profiles.json`, if present.
4. `factorio-toolset/tool-ui.json` value `profiles_json`.
5. Toolset default `factorio-toolset/modlist-profiles.json`.

At startup the harness prints `Profiles: <path>` so you can see which source was used. If no `mod_profile` is configured and no `--mod-profile` is passed, the current `mod-list.json` is left unchanged. After the run, the previous `mod-list.json` content is restored exactly unless `--keep-mod-list` is used.

## Startup Setting Profiles

Startup settings are a separate matrix axis from mod-list profiles and Lua test profiles. Define them in `tools/test/harness.json`:

```json
{
  "setting_profiles": {
    "default": {},
    "steam_off": {
      "some-startup-setting": false
    }
  },
  "setting_profile_groups": {
    "all": ["default", "steam_off"]
  }
}
```

`--setting-profile NAME` runs with one startup setting profile. `--all-setting-profiles` runs the selected Lua test profiles against every profile in `setting_profile_groups.all`; if that group is missing, it uses all defined setting profiles. The optional `debug_setting` is still mixed into every setting profile unless it is disabled on the CLI.

The harness writes `mod-settings.dat` immediately before each Factorio run and restores the exact previous bytes immediately afterward. Startup settings therefore belong in Python, not in `runner.lua`, because Factorio reads them before the data stage.
## Running

```powershell
python F:\Games\Factorio_ModTest\mods\Toolsets\testharness\run_tests.py --mod-root F:\Games\Factorio_ModTest\mods\Ingredient_Scrap --profile default --no-color
python F:\Games\Factorio_ModTest\mods\Toolsets\testharness\run_tests.py --mod-root F:\Games\Factorio_ModTest\mods\Ingredient_Scrap --all --no-color
```

Useful overrides:

```powershell
python F:\Games\Factorio_ModTest\mods\Toolsets\testharness\run_tests.py --mod-root F:\Games\Factorio_ModTest\mods\Some_Mod --report-relative Some_Mod/test-report.json --artifact test-report.json
```

## Porting To Another Mod

1. Add the Lua-side test files to the target mod.
2. Add `tools/test/harness.json`.
3. Add `tools/test/modlist-profiles.json` for named mod-list profiles and optional `profile_groups.all`.
4. Add a hidden startup setting if the mod should only generate tests in debug mode.
5. In data/final-fixes, put the report into a `mod-data` prototype.
6. In control stage, write that report to `script-output`.
7. Run this harness with `--mod-root <target mod root>`.

The Python side does not need to live inside the target mod.
